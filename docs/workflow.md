# レビューワークフロー

画面上のフィードバックを記録し、修正や共有につなげます。起動方法は [クイックスタート](./getting-started) を参照してください。

## 画面を見ながら注釈を付ける

- **DOM ノード選択 (`N`)**：ボタンや見出しなど、特定の要素を指摘します。
- **矩形範囲 (`R`)**：レイアウトの余白や画像の一部など、範囲で指摘します。
- **閲覧 (`V`)**：対象ページを閲覧するモードへ戻ります。

PC・タブレット・スマートフォンの表示を切り替えて、画面幅ごとの問題を確認できます。注釈はスレッド、状態、履歴、フィルターで管理できます。

::: tip 具体的なフィードバックにする
「見づらい」だけでなく、「このボタンの背景色と文字色のコントラストを上げてほしい」のように、対象と期待する変更を添えると伝わりやすくなります。
:::

## AI に修正を依頼する

対応する coding agent CLI をインストール・認証してから、左上の設定画面で AI を構成します。

**対応 CLI：** OpenCode / Claude / Codex / GitHub Copilot / Pi / カスタム CLI。

- **AI プラグイン**：CLI の選択、外部 AI コマンドの登録・検証を担当します。
- **annotation-workflow プラグイン**：並列数や自動実行ポリシーを設定します。

注釈をもとに AI に修正を依頼し、結果の画面とコードの差分を確認してください。

### カスタム CLI

依頼文を渡す `{prompt}` を、コマンドに **1 回だけ**指定します。

```text
agent-command --prompt {prompt}
```

コマンドは shell を介さず実行され、登録前にツール利用能力が検証されます。

::: warning 認証情報の扱い
API キーやトークンはコマンドに書かず、各 CLI の認証設定や環境変数を使ってください。AI の修正は必ず内容を確認し、必要なテストを実行してください。
:::

## GitHub Issue として共有する

1. 対象リポジトリにアクセスできるアカウントで `gh` を認証します。
2. 「GitHub Issue にする」を選びます。
3. AI が生成した編集可能な下書きを確認し、必要に応じて修正します。
4. 内容を確認してから GitHub に追加します。

公式 `github-issue` プラグインは初回起動時に自動導入されます。GitHub の認証は自動では行いません。

## キーボードショートカット

| キー | 操作 |
| --- | --- |
| `V` | 閲覧モード |
| `N` | DOM ノード選択 |
| `R` | 矩形範囲選択 |
| `⌘+Enter` / `Ctrl+Enter` | 注釈・返信・Issue の送信 |

## ワークフローを拡張する

プラグインでストレージ、AI、画面遷移解析などを追加できます。[開発者ガイド](./developers) から目的別のリファレンスへ進めます。
