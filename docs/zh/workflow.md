# 审阅工作流

在页面上记录反馈，再将其转化为修改或共享任务。安装方法请参阅[快速入门](./getting-started)。

## 在页面上添加批注

- **DOM 节点选择 (`N`)**：指出按钮、标题等具体元素。
- **矩形区域 (`R`)**：标记布局间距、图片局部等区域。
- **浏览 (`V`)**：返回目标页面的浏览模式。

在桌面、平板和手机视图之间切换，检查不同屏幕宽度下的问题。通过讨论串、状态、历史和筛选器管理批注。

::: tip 让反馈更具体
与其只说「看不清」，不如描述为「请提高这个按钮文字与背景的对比度」。同时指出位置和期望的改动，能让反馈更容易理解。
:::

## 请求 AI 修改

安装并认证支持的 coding agent CLI，然后在左上角的设置页面配置 AI。

**支持的 CLI：** OpenCode / Claude / Codex / GitHub Copilot / Pi / 自定义 CLI。

- **AI 插件**：负责 CLI 选择以及外部 AI 命令的注册和验证。
- **annotation-workflow 插件**：配置并行数量和自动执行策略。

基于批注请求 AI 修改，然后检查修改后的页面和代码差异。

### 自定义 CLI

在命令中使用 `{prompt}` 传入请求内容，且**只能出现一次**：

```text
agent-command --prompt {prompt}
```

命令不通过 shell 执行，注册前会验证工具使用能力。

::: warning 凭据与生成的修改
请勿将 API 密钥或令牌写入命令。请使用各 CLI 的认证设置或环境变量。务必检查 AI 生成的修改并运行相关测试。
:::

## 创建 GitHub Issue

1. 使用有权访问目标仓库的账号完成 `gh` 认证。
2. 选择创建 GitHub Issue 的操作。
3. 检查 AI 生成的可编辑草稿，并根据需要修改。
4. 确认内容后，再添加到 GitHub。

官方 `github-issue` 插件会在首次启动时自动安装。GitHub 认证不会自动完成。

## 键盘快捷键

| 按键 | 操作 |
| --- | --- |
| `V` | 浏览模式 |
| `N` | 选择 DOM 节点 |
| `R` | 选择矩形区域 |
| `⌘+Enter` / `Ctrl+Enter` | 提交批注、回复或 Issue |
